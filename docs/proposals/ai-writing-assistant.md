# 写作 AI 助手演进提案

状态：**提案保留，暂缓实施**。记录日期：2026-11-15。当前工程优先级是写作引擎、多文件投影与源码定位；本文不代表已经实现或发布的功能，不改变现有 AI 和 MCP 行为。

## 产品目标与边界

让 AI 理解作者正在写的内容和工程依赖，在同一个写作环境中解释、校对和提出可审阅的修改。普通写作保持轻量，跨文件任务才展示任务过程。作者随时可以直接写 TeX；没有模型或网络仍能完成编辑、编译和导出。

同时保留两种接入：作者自填 API／本地模型，以及已经安装、由作者自行登录的外部智能体。两者共享工程上下文和修改提案协议，不假定工具、会话、权限或登录方式可以互换。本文借鉴 [Papilot](https://github.com/PapilotAI/papilot) 的工程任务与 PDF 反馈循环；调研基于提交 `9006632d4aeaba1e3333282adf0203991fab78cb`，尚未复制其实现。未来复用代码时单独核对 MIT 许可与署名。

## L0–L3 的入口安排

| 层级 | 在 TeXPro 中的职责 |
| --- | --- |
| L0 无感增强 | 整理作者已授权的上下文、绑定版本、去重和拒绝过期结果；不后台上传全文，不让 AI 接管确定性的 TeX 解析 |
| L1 原位增强 | 选区校对、解释公式、补写一小段；结果就近呈现，接受后形成一次可撤销的修改 |
| L2 按需工具 | 扩展现有 AI 助手，承载多轮交流、上下文选择、附件与修改审阅 |
| L3 独立任务 | 只有跨文件改写、参考文献修复或长期工程任务确需持续阶段和多区域审阅时，复用既有工作空间机制；不为每一种 AI 能力新建页面 |

层级由任务复杂度决定。助手关闭后恢复当前文件、光标、选择和滚动。不要为一次校对要求作者创建任务，也不要把专业任务挤进难以审阅的小弹层。

## 接入与能力协商

直接模型路径提供流式回复、取消、模型配置和明确的上下文预算。API 凭据沿用系统密钥存储边界；本地模型也需要明确说明请求目标和提供方能力，不以“本地”推定全部处理都在设备内。

外部智能体通过独立适配器报告可用状态、版本、模型、工具调用、权限请求、取消能力与会话恢复能力。检测仅确认程序是否可用，不自动安装、登录或启动长任务。优先标准协议；具体客户端的协议、认证和可用性在实施时再核实。

适配器与界面解耦：统一消息、任务状态、工具请求、提案、诊断与使用量事件；不支持的能力明确显示，不伪造统一能力。切换提供方可以新建任务，不承诺迁移另一提供方的完整会话。

## 工程上下文

上下文必须说明来源是编辑器缓冲区还是磁盘，以及主文件、当前文件、选区和依赖的版本。以共享主文件解析与写作引擎为依据，按任务最小化选择文件；用户可查看将发送的内容。图片、参考文献和编译日志按需加入，不递归打包整个工程。

排版问题可提供当前编译诊断和相关 PDF 页；PDF 必须绑定产生它的源码版本。编辑器投影与正式排版有不同精度，不能把一张看似正常的预览当成排版正确证明。

## 修改提案与工具权限

模型输出解释与结构化修改提案。提案包含文件身份、原始源码哈希、替换范围、原文及变更理由。应用端自行验证边界和版本，不信任模型给出的路径或位置。作者继续编辑后，失效提案拒绝应用，并支持重新读取后生成。

单文件接受通过 CodeMirror transaction 落地，保留撤销。跨文件修改复用已有成组编辑与保存机制，逐文件展示差异，失败时给出可恢复状态；不把内存回滚称为崩溃事务。

允许模型读取上下文、执行工具，以及作者接受文稿修改，是三个不同决策。危险工具不能因作者同意校对而自动获权。工具执行沿用已有 IPC／MCP 的显式能力，不新增通用任意 shell 接口。

复杂任务可按需使用隔离快照或 Git worktree，但普通写作和非 Git 工程不能被强制初始化 Git。worktree 不构成操作系统安全沙箱，也不能替代权限控制。

## 任务和审阅

任务具有排队、运行、等待作者、已取消、失败、完成等明确状态。取消后阻止旧事件、补丁和 PDF 回写；恢复能力由提供方声明。失败保留已产生的解释与提案，并允许重试；不能把取消按钮只做成隐藏消息。

基础审阅以源码差异为准；需要判断版式时，在相同工具链下比较对应 PDF。区分文字修改、引用／编号影响和排版变化，不声称 PDF 差异能自动证明事实、数学或引文正确。

任务记录保存在本机，可清理；对话、日志、密钥与工程备份具有不同生命周期。远程存储或协作必须是另行启用的能力。

## 视觉与连续写作

沿用 PRODUCT.md、DESIGN.md 和桌面三主题的纸面语言、字体角色、共享 token 与 Lucide 图标。助手是辅助写作的侧面工具：轻分隔、清楚的文字层次、一处主要行动，不用聊天气泡和厚卡片淹没正文。

短回复、工具事件、错误与待审阅修改具有不同层级；运行过程可收起，必要的权限和错误不隐藏。流式文字不反复抢滚动，键盘操作和关闭后焦点返回遵循现有共享机制。减少动态效果设置下关闭非必要动效。

## 实施顺序和验收

- 先完成当前写作引擎的共享上下文、源码范围、过期保护与多文件回归，再让 AI 消费这些契约。
- 第一阶段完善现有助手的消息、流式、取消、上下文预览和原位修改提案，不替换当前已有写作任务。
- 第二阶段增加外部智能体适配与明确的工具权限，验证真实客户端和失败恢复。
- 第三阶段按实际需求增加跨文件任务、源码／PDF 联动审阅和本地任务记录。
- 最后评估模板／Skill：校对、翻译、公式解释、引用修复等任务使用版本化模板，不把私有聊天和模型输出变成宿主规则。

验收覆盖未保存缓冲区、模型不可用、断流、取消、快速换工程、过期补丁、跨文件失败、组合输入、撤销、主题、语言与键盘。若修改插件或 MCP 公开契约，先尝试兼容适配；确有破坏时提供明确的版本、迁移和回退文档。本文不提前承诺所有客户端、所有模型或完整自动写论文能力。
