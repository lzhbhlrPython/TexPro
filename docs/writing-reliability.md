# 写作可靠性维护

本文记录代码边界和验证入口；普通 `.tex` 源码始终是文档原件。

## 保存与文件操作

- `src/app/saveQueue.ts` 串行保存，防止旧写入覆盖新写入。保存使用快照；期间继续输入会保持脏标记。
- 原生关闭通过 `electron/window-close.cjs` 请求渲染进程保存所有打开的脏文件，确认成功后关闭。保存失败或超时保持窗口打开，允许重试。
- 文件改名、目录改名、文件移动统一经过 `project-operations.cjs`：先准备引用修改，再移动和写入；写入失败时恢复已改文件与原路径。进程崩溃、断电等不属于此内存回滚的保证范围。
- 引用更新只处理可解析的常规命令参数和 `% !TeX root`；含动态宏的路径保留源码。注释和逐字环境示例不会被替换。
- `src/app/fileOperations.ts` 将磁盘引用修改映射到全部打开缓冲区，并保留 IPC 等待期间的输入。重叠修改保留输入并提示检查。光标、滚动和 CodeMirror 会话随路径迁移。

## 布局、字体与诊断

布局工具只替换 `% TeXPro layout begin/end` 中的内容，保留作者已有的宏包及其选项；已有 geometry 时使用 `\geometry{...}` 更新布局。文档类只更新纸张、字号和分栏选项。

字体解析结果分为匹配、不匹配、无法验证。缺少 `fc-match` 或 `pdffonts` 时不得显示检查通过。此处是字体声明与 PDF 嵌入检查，不能证明每个字形均有覆盖。

诊断解析保留 fontspec 等宏包的续行信息及行号，问题列表悬停可读完整消息。

## 界面与加载

备份、文献、模板和字体面板共用焦点管理；Tab 限定在面板内，Escape 关闭，关闭后返回正文。文献面板有修改时先询问保存；取消或保存失败继续留在面板。

PDF.js 与 PDF 面板按需加载。主入口构建体积从约 1.83 MB 降到约 1.38 MB（未压缩），仍超过 Vite 默认的 500 kB 提醒阈值。光标在同一预览区域内移动时复用装饰；源码修改、区域边界、预览配置或审阅状态变化仍完整解析，以保留嵌套结构的正确性。

## 验证

```sh
npm run typecheck
npm run test:regression
npm run build
npm run verify:release
npm run test:flow:ui
```

桌面回归使用临时用户目录和测试工程，覆盖智能转换、引用维护、恢复位置、三种主题、弹层键盘操作和关闭前保存，不触碰日常项目。

附带仓库分析的核对结论：App 编排集中、服务体积大、全量预览扫描和文件操作后的旧缓冲区风险成立；原 `saveAll` 实际为顺序保存，不能据该分析称其原来是并行保存。协作权限和整体状态架构需要独立审查，本文不将其视为已解决。

## macOS 退出收尾

本机 macOS 27 / Electron 44.9.1 在 Chromium 线程池原生收尾阶段可能无限等待；不加载本项目代码的最小 BrowserWindow 程序同样复现。`app.exit`、`process.exit` 和主线程 JS 定时器无法解除已阻塞的原生阶段。上游相近的采样与背景任务等待问题见 [Electron #55647](https://github.com/electron/electron/issues/55647)。

`electron/quit-watchdog.cjs` 只在 macOS 的不可取消 `quit` 事件启动独立收尾进程。此时渲染进程已确认文档保存，`will-quit` 清理已执行。它等待 5 秒，查询自己的**实时父进程**；若父进程仍是本应用，则清理该进程。正常退出后收尾进程被系统重新托管，父进程检查不通过，自行结束；不会因 PID 后续复用而结束其他程序。取消退出、保存失败、单独关闭 macOS 窗口但未退出应用，均不会启动兜底。

这是原生运行时停留的应用级兜底，不是 Chromium 源码修补。Windows 与 Linux 继续使用系统正常退出。桌面测试同时校验退出前落盘内容和进程真正结束，不再以打印“保存成功”代替完成退出。测试只在收到同 PID、退出码 0 的不可取消 quit 报告时，接受该兜底产生的 SIGKILL；崩溃、超时和失败退出仍判失败。
