# 文档维护规则

## 内容分工

| 文档 | 维护内容 |
| --- | --- |
| 根 README | 产品简介、安装、运行与文档入口 |
| AGENTS.md | 协作边界和必须遵守的规则 |
| PRODUCT.md / DESIGN.md | 产品原则 / 设计语言与真实 token 来源 |
| docs/ | 工程架构、契约、开发及验证 |
| 官网 docs / en | 使用与开发任务的中英文指南，同 slug |
| 官网 blog | 应用开发的历史决策与实际验证；不写官网改版日志 |
| mcp/README.md | 外部 MCP 安装、工具与信任边界 |
| 产品页 README | 站点内容、布局边界、构建和生成产物 |

## 写法

博客 tags 使用逗号分隔的纯标签，不含方括号或反引号，页面、搜索与 feed 的标签保持一致。包管理器统一写作小写 npm、yarn。官网代码围栏应标注真实语言，如 sh、powershell、tex、json；仅输出或日志使用 text。代码高亮不改变命令，也不能代替说明命令在哪个目录执行、预期结果与应用中下一步。

参考 [Google 开发者文档风格指南](https://developers.google.com/style/highlights)：用直接、具体的句子说明任务，前提放在步骤前，顺序操作用编号列表，代码用代码字体，链接说明目标。英文标题使用 sentence case。中文版保持自然中文，不把界面一半写中文一半写英文。

每篇任务文档回答：适用于谁、需要什么、怎么操作、结果是什么、失败怎么办、如何验证。技术标识和作者 TeX 源码保持原样。未知平台、未签名包和近似 SyncTeX 映射需要说清，不写没有证据的性能、兼容性或隐私承诺。

不固化行数、IPC 数量、测试条数、面板数量和安装包数量作为维护契约。需要统计时给出查询方法或注明历史日期。测试报告和博客中的历史数字保留历史语境，不冒充当前状态。

## 官网同步

程序主体开发侧维护简体中文博客，以及其他官网页面、界面文案和文档的简体中文／英文双语。其他语种的接入、翻译、构建和校验交由第三方 AI；主体开发侧维护独立的文案与内容入口，并提供变更范围、真实界面名称和验证要求，不代写其他语种正文，也不覆盖第三方译文。具体入口、当前限制和交接清单见[官网翻译交接指引](website-translation.md)。这项分工不降低中英同轮同步要求，也不要求为博客创建英文副本。

文档操作步骤使用该语种界面的实际文案，按桌面英文源目录、对应语言包、原生菜单与相关工具的翻译源核对；中文步骤不混入英文按钮，英文步骤不沿用中文按钮。品牌、命令、文件路径、配置键、API／协议及源码示例保留技术原文。尚无翻译的真实界面明确注明，外部编译器和服务错误保留原文并解释，不编造软件中不存在的译名。

官网篇目保持 slug 和站内链接稳定；各语种统一放在 `product-page/src/content/docs/{locale}/{slug}.md`，当前 `zh/` 与 `en/` 平级、同名同 slug。文档根目录仅保留共享索引和模块，不能把中文正文放在根目录作为特例。front matter 包含 slug、title、group、order、summary。只用站点解析器支持的标题、段落、列表、代码块、引用、表格和行内标记，不写 Mermaid、HTML 或复杂嵌套列表。目录调整同步 glob、搜索、统计、生成器与测试夹具，公开文章链接仍为 `/docs/:slug`。

内容自动被 glob 加载，不需要改路由、组件、依赖或布局基线。先后运行 `pnpm check:layout`，再运行类型检查与构建。生成的 feed、llms、sitemap 和 robots 由 Vite 生命周期调用脚本生成，不手改。修改生成器需要单独核对发布范围；只更新内容不授权改页面设计。

## 审计和接手

旧审计要保留日期，增加后续核对状态与源码依据；不能长期把已修复事项放在当前待办。新会话先看 `docs/README.md`，然后按任务阅读，避免一次加载全部博客和截图。

公开规范与产品文档可以进入 Git。私人聊天、凭据、superpowers 计划及临时验收记录不可提交。生成产物只按现有站点约定维护，不把缓存、dist 或本地环境文件混入。

## 官网文档的读者分区

使用入口 `/docs` 直接阅读 start，开发入口 `/developers` 直接阅读 dev-setup；共用文章阅读器，不设导览首页，保留 `/docs/:slug` 的文章链接。开发 Skill 归入 AI 协作。按规范中文 group 分类，开发和 AI 协作进入开发区，开始、使用、参考和关于进入使用区；实现与生成器共用 product-page/src/content/docs/sections.mjs，英文不独立判断。安装／卸载扩展、语言包切换面向使用者，SDK、qwertysay、Skill、MCP 和应用架构面向开发者。维护新篇目时检查目录、侧栏、前后篇、搜索、llms 与 sitemap；跨区推荐可用正文链接或分区首页，不混入另一套侧栏。

## 国际化资源的颗粒度

菜单、按钮与短状态使用语义键 JSON；文档、彩蛋和长篇说明使用按语言保存的整篇 Markdown，统一渲染。不要为段落和句子分配 UI 翻译键。中文指南的操作名称取自中文包，英文取自英文 JSON，保持语义键身份稳定；修改目录格式或语言包兼容性时同步 [翻译维护](language-packs.md) 与第三方交接指引。
