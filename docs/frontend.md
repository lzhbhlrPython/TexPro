# 前端设计与实现约束

适用于桌面渲染层和产品页前端。本文规定新增与修改代码的验收要求；[DESIGN.md](../DESIGN.md)记录视觉语言与实际 token，[技术契约](technical-contracts.md)说明数据不变量。既有代码不完全符合时按本次任务逐步修正，不据此发起未授权的全局改版或重构。

## 1. 表面与模块边界

| 范围 | 代码入口 | 约束 |
| --- | --- | --- |
| 桌面编排 | src/App.tsx、src/app/ | 保留工程与缓冲区身份，抽取任务相关逻辑，不继续堆叠无关面板实现 |
| 编辑器 | src/editor/ | CodeMirror transaction 与源范围是修改入口，React 不直接重建文档 |
| 桌面工具 | src/components/、src/app/lazyTools.tsx | 可选辅助按需加载，隔离渲染异常，不能拖垮正文 |
| 纯逻辑 | src/lib/ | 可独立验证的转换、解析与模型，不引入 UI 生命周期 |
| 桌面样式 | src/styles/、src/editor/theme.ts | 选择写作、PDF、图示等所属文件，不随意追加到全局 app.css |
| 官网 | product-page/src/ | 沿用现有路由、Ant Design 和内容加载机制，不与桌面 UI 共用状态 |

渲染层通过 src/api.ts 与 preload 暴露的接口访问原生能力，不引入 Node API、任意 IPC 或新的通用命令执行入口。官网内容任务不授权修改壳层。

本项目设计工作必须使用 Codex 专用的 `antd-admin-template` 技能辅助，入口为已安装技能的 SKILL.md，再按需读取设计语言、组件复用和交互参考。这是用户对 TeXPro 的持续明确授权；其他项目仍须用户主动要求 Ant Design / antd 或点名技能，不能因已有依赖、后台或看板需求自行调用。技能不随项目分发，其模板与默认配色不覆盖本项目 DESIGN.md、连续写作原则、桌面组件体系或产品页修改范围。官网核对实际 antd 版本与组件 API；桌面借鉴设计方法与一致性检查，继续复用既有组件和主题。

## 2. 视觉实现

- 桌面复用已有 --bg、--panel、--paper、--text、--editor-text、--accent 及状态变量；编辑正文与工具栏色彩域分开，不拿工具栏文字色直接画在纸面上。
- 官网复用 Ant Design token、--site-*、已有字体和动效变量。颜色例外须有语义和明暗依据，不能为一个组件新建无关色板。
- 桌面 paper、studio、night 分别验收；官网 light、dark 分别验收。不能将 studio 简单当作全暗主题，也不把官网直接套成桌面三主题。
- 桌面图标用 Lucide，官网沿用 Ant Design。相同操作的名称、图标、危险态、禁用态和快捷键展示保持一致，不再引入第二套图标或 UI 库。
- 字号、间距、圆角和阴影从所属表面的既有规则选用。内容、表格、占位符、参考文献不因组件库方便而一律卡片化。
- 屏幕主题不改变作者字体、图稿指定颜色或正式 PDF。新增设计规则同步 DESIGN.md；只改规范不能声称界面已达标。

## 3. 连续输入与源文

正文、公式、表格、乐谱、电路与结构式共享写作流程。普通输入不得强制进入工作室、配置表单或提交仪式。可视化可以辅助，源码必须可达，复杂输入不能解析时保留原文。

修改经过 CodeMirror transaction，保留选择映射和撤销；避免通过全文替换、直接改 DOM 或重新创建 EditorState 实现局部更新。可编辑投影须把输入接回同一文档历史，不建立第二份内容原件。

IME 组合期间不得替换正在输入的投影或抢焦点；补全确认与结构快捷键要考虑 composing。中文、英文、粘贴、撤销和跨可视块选择都属于基本交互，不只测试鼠标点击。

## 4. 异步状态与回写

请求开始记录工程、文件、请求序号或 runId；等待结束后重新校验，过期结果丢弃。涉及源文的辅助操作使用 writingTargets 的映射与原文校验，不能只记旧 offset。

取消、卸载、切工程、改名或连续发起新请求后，旧预览、诊断、AI 或工具结果不得写回新上下文。加载、失败、空结果分别表达，提供适当重试或源码入口，不将异常仅留在 console。

保存只确认提交快照；保存期间继续输入不能被清为已保存。编译与依赖插入沿用真实主文件和保存队列，不能因当前组件方便自行选入口。

## 5. 焦点、键盘与反馈

普通操作优先保留写作位置。明确导航才跳转；引用查阅、预览更新与辅助反馈不默认离开段落。桌面对话框沿用 src/hooks/useDialogFocus.ts 的机制，官网沿用 Ant Design 弹层的焦点机制；分别检查初始焦点、Tab 边界、Escape 和关闭后的返回目标，不把桌面 hook 硬套到站点。

图标按钮有名称，焦点可见；hover 不能是唯一操作入口。快捷键核对 CodeMirror 和系统冲突，展示按平台格式化。危险操作说明对象与影响，保存失败保留内容；取消不是失败，也不应输出错误警报。

状态检查至少覆盖适用的默认、hover、focus、selected、disabled、loading、error 和 empty。不要为了凑齐状态发明不存在的交互。成功、失败和进度反馈不能只靠颜色，也不能让常规输入不断弹通知。

## 6. 布局、动效与性能

缩放、窄窗口、长路径、长英文、日志和代码块不能挤掉必要操作；溢出内容局部滚动。滚动定位操作正确的容器，不滚动整个软件来显示 PDF 中的目标。

正文输入优先，不在每次渲染、鼠标移动或 decoration 构建中增加无界扫描、同步编译或重型 import。复用已有缓存、请求去重与按需加载；缓存失效包含文件和导言区身份。

动效说明状态和关系，不延迟输入或关闭；官网沿用已有时长与 Reveal 节奏。reduced motion 下内容可见、操作完整。正文滚动补偿尊重用户新滚动，不用持续回弹强行锁定旧位置。

## 7. 文案与 i18n

桌面可见字符串走 src/i18n.ts，官网走 product-page/src/i18n/。同轮补齐中英文，保持菜单、命令面板、提示和帮助名称一致；LaTeX、PDF、MCP 等技术标识保留。

错误说明发生什么、影响哪里和下一步。不给普通用户展示 runId、IPC 或内部缓存配置，除非进入明确的诊断视图。官网文档同时维护英文同 slug，博客保持简体中文并说明语言。

## 8. 验收与提交

| 修改 | 必要证据 |
| --- | --- |
| 桌面前端逻辑 | 类型、相关回归、构建；说明失败和跳过 |
| 编辑器或辅助交互 | 原生输入、IME、选择、撤销、焦点、滚动、切文件及过期结果检查 |
| 视觉组件 | 所属主题、长中英文、键盘、缩放与必要窄屏；颜色组合实际检查 |
| 官网壳层 | 版式锁、类型、构建、明暗、窄屏、reduced motion、Pages 子路径；涉及打印时检查打印 |
| 仅文档 | 链接、源码事实、双语和生成产物；不宣称完成 UI 验收 |

具体命令见 [开发指南](development.md)。修改完成同步设计与文档，在当前任务分支及时提交并按已有授权推送；不是每个组件或每次消息都新建分支。通过构建不等于原生交互通过，静态检查不等于无障碍认证。
