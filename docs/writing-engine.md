# 工程感知的写作引擎

写作引擎把普通 TeX 源码投影为便于连续输入的界面，不替代完整 TeX 排版。正式 PDF 仍由工程选定的本地工具链生成。即时语义投影与真实 TeX 排版回退共同服务连续写作；源码语法高亮、补全和诊断独立保留，不把高亮当作所见即所得。此次重构不引入新的文档格式、工作空间或预览模式。

## 按职责定位代码

| 模块 | 职责与边界 |
| --- | --- |
| `electron/services/tex-source-core.mjs` 及 `.d.mts` | 共享平衡范围、注释／逐字环境扫描和文档边界；无 Node、React 或 DOM 依赖 |
| `electron/services/writing-path-core.mjs` | 浏览器与 Node 共用的词法路径；不承担文件授权 |
| `electron/services/writing-context-core.mjs` 及 `.d.mts` | 有界静态导言区引用、宏与图片解析；文件读取通过回调注入 |
| `electron/services/writing-source.cjs` | 自动上下文读取的原生路径、真实路径和大小边界 |
| `electron/services/writing-context.cjs` | MCP／本地图示预览的磁盘适配 |
| `electron/services/native-writing.cjs` | 不可变临时工程、未保存覆盖、原生编译、缓存、SyncTeX 区域和会话清理 |
| `src/lib/writingEngine/native.ts`、`src/hooks/useNativeWriting.ts` | 通用回退候选、原生请求类型、组合输入与异步版本门控 |
| `src/editor/projection/nativeWidget.ts`、`nativePdf.ts`、`nativeText.ts` | 原生区域、普通文字重排、图形保真、共享资源与反向定位 |
| `src/lib/writingEngine/includes.ts`、`useWritingComposition.ts`、`projection/includeWidget.ts` | 有界章节发现、缓冲区优先与连续子文件投影 |
| `src/editor/WritingSurface.tsx`、`composedEditing.ts` | 在同一纸面挂载文件编辑器，路由写作命令、守卫陈旧输入并保留每文件历史 |
| `electron/services/geometry-core.mjs` | 绘图语法、包依赖、歧义消解和必要的预览包装 |
| `src/hooks/useProjectWriting.ts` | 缓冲区优先的上下文加载、组合输入门控、去抖和过期结果丢弃 |
| `src/lib/writingEngine/source.ts` | 每个源码版本的只读扫描模型 |
| `src/lib/writingEngine/engine.ts`、`types.ts` | 提供器注册、稳定优先级、范围验证、失败隔离与每实例缓存 |
| `src/lib/writingEngine/providers/` | 公式、图像、文字样式、表格与图示的语义投影 |
| `src/editor/visual.ts` | CodeMirror 选择、修订、冲突归属和 decorations；保留现有音乐／占位符等专业交互 |
| `src/editor/projection/widgets.ts` | DOM、点击回源码和异步图稿生命周期 |
| `src/lib/texMath.ts`、`texInline.ts` | 正文与表格共用的受限数学渲染和内联源码偏移 |
| `electron/services/synctex.cjs` | 桌面与 MCP 共用的参数、进程与结果解析；保留 `tex.cjs` 的原有导出 |
| `src/lib/pdfSync.ts` | PDF.js viewport 的缩放、裁切、旋转与 SyncTeX 坐标转换 |

纯核心的 `.mjs` 是维护源码，配套 `.d.mts` 描述同一契约；不要再写一份浏览器或 MCP 专用解析器。`texDocument.ts` 保留写作操作与表格模型，并重导出共享扫描函数。添加共享模块时同步 ASAR 外依赖清单和真实普通 Node 验证。

## 数据流和身份

主文件仍由 `project-root.cjs` 唯一确定；当前子文件不会改变入口。上下文的工作目录采用工程根目录，与常规编译一致，而不是当前标签页目录。未保存的主文件或样式文件优先于磁盘；主文件未打开时也能加载上下文。

上下文加载只读取导言区的静态、顶层、字面量 `input/include`，不读取正文的所有章节，不执行 TeX 或展开任意宏。递归深度、文件次数、单文件和总字符数均有边界；循环、缺失和无法读取的依赖降级。注释、逐字内容、宏体与条件分支不会被当成无条件文件读取。动态路径、宏包搜索路径、类别码、任意条件及复杂局部作用域仍由真实 TeX 解释。

投影范围是当前原始文档的 UTF-16 偏移，不是展开导言区的位置、拼接后的章节位置或屏幕坐标。提供器不得写源码、修改源模型、读取磁盘或操作焦点。CodeMirror 适配层决定当前选择、修订范围及专业对象之间的归属；原生回退未完成或无法可靠映射的内容保持源码。输入与撤销继续通过现有 transaction。

异步上下文结果检查请求归属；换工程、依赖变化、组合输入和卸载时丢弃旧结果。只移动普通段落光标复用投影；源码、导言区或工程上下文变化使对应计划失效。公式缓存包含宏定义，图片刷新包含上下文版本；图稿缓存包含展开后的导言区。不要把取消或缓存命中当成来源身份校验。

## 增加内部提供器

在 `providers/` 中实现 `ProjectionProvider`，在 `createTexWritingEngine` 中显式注册。ID 稳定且唯一，优先级为有限数值。输出 `kind`、原始源码的 `from/to` 和语义数据；所有范围必须有效。一次提供器输出不合法时丢弃该提供器的本次结果，其他提供器继续工作。

适配层必须显式实现新 kind，并决定选择进入后的源码呈现、专业对象嵌套、点击位置和销毁。提供器的高优先级决定计划顺序；它不自动替代适配层的冲突规则。测试正常内容、嵌套、注释、逐字环境、未完成输入、失败、上下文变化及原始偏移。

这是内部 TypeScript 接口，**不是新的插件 SDK 或可执行插件加载入口**。不要将任意第三方代码传入注册器，也不要以此绕过现有扩展能力审核。以后公开时另行版本化。

## 当前支持与回退

图片按工程工作目录及字面量 `graphicspath` 查询；支持省略常见扩展名，PDF 图像通过既有 PDF.js 高分辨率路径显示第一页。未知、动态和未索引的资源保留源码，不猜测子文件目录的同名文件。插入图片时也生成相对工程工作目录的路径；已有错误的子文件相对路径不会被静默改写。

公式支持可由 KaTeX 解释的简单必选参数宏；文本支持明确的单参数字体包装和受检 HTML 六位十六进制颜色包装。这些快速提供器之外的自定义宏、环境、复杂表格与失败的数学公式会成为原生回退候选，由工程自己的 TeX 工具链解释。不能可靠映射时保留源文，不生成会丢失宏或合并单元格的简化表格。

XeLaTeX 工程仍用 XeLaTeX，不为了实时预览改作者的引擎、字体、模板或宏包。rtex-ts 继续是适用 LuaLaTeX 工程的内部加速路径，见[实时预览](realtime-tex.md)。

## 原生排版回退

这是 L0 编译基础与 L1 原位呈现，不新增模式选择。开启可视模式和自动编译、编译策略非手动时，在暂停输入后请求原生预览；遵从关闭自动编译的选择。正式编译的保存规则保持不变，原生预览本身不调用保存。

会话按工程入口、引擎与可视启用身份隔离。读取工程真实路径，拒绝外部符号链接和循环；异步复制依赖到系统临时目录，再覆盖当前打开的未保存 TeX／样式／文献缓冲区。原目录不写入。保留作者文档类、引擎、字体、宏包、`.latexmkrc` 与未知配置字段，只在副本指定相同主文件及内部构建目录。它复用本地编译工具链，**临时副本不是 TeX 或构建配置的执行沙箱**。

缓存键覆盖引擎、入口、配置、文件清单及大小／修改时间／状态时间、未保存覆盖的内容。相同快照切换文件可复用已完成的 PDF；不是每次切换都重新编译。每会话最多保留两个已完成副本。新请求取消旧编译并等待其结束，临时目录不会在进程仍写入时删除；关闭工程、渲染进程结束和卸载清理会话。

独占一行的字面量 `input/include` 原位展开，子文件使用同一个 `EditorPane` 的高亮、补全、表格、投影、输入法与写作操作。`WritingSurface` 通过 React portal 挂载文件编辑器；普通输入修改各自 CodeMirror 文档与宿主缓冲区，不创建可写的拼接文档。焦点决定当前写作目标，父文件标签页与工程主文件不随之切换。嵌套章节共用正文列与外层滚动容器；方向键可在引用边界进出文件。展开最多 64 文件、8 层、400 万字符，循环或缺失时保留引用源码并提示。不把整页 PDF 嵌入正文。精确分页、浮动、目录与编号以正式 PDF 为准。

一个文件在同一纸面只拥有一个可写编辑器；重复引用保留同步的只读投影，点击定位真实文件。协作会话继续按单文件运行，此时展开章节保留只读投影。文本选择、复制／剪切、全选与普通撤销限制在当前文件，尚无跨文件文本选区或全工程按时间排列的普通撤销栈；已有项目标签改名仍成组撤销。文件切换沿用会话缓存，不声称重启后保留撤销历史。

嵌入编辑器的输入事务先核对源文与当前工程缓冲区，拒绝覆盖较新的内容；显式外部刷新使用独立 annotation，保留选择映射且不新增用户撤销项。辅助工具的捕获目标按文件路由，标签改名和移动引用更新同时映射所有已挂载编辑器。保存继续走 `SaveQueue`，自动保存覆盖所有打开的脏缓冲区。上下文修订不会让章节发现结果暂时消失，从而避免输入法结束或导言区刷新卸载编辑器。切工程、文件移除及窗口关闭仍清理对应视图。

子文件不透明环境或宏段落查询每个源码行，验证返回盒子反向定位仍属于该文件和区域，合并同页裁切。PDF.js 提取出的可靠普通文字回到宿主字体与行距，并记录原始文字位置供点击定位；含数学、图形、作者颜色、复杂字体或不可靠元数据的区域保留高密度图形。没有可靠映射的区域不猜测。源范围、PDF 与 SyncTeX 均属于同一不可变副本。

结果回写同时检查请求身份、工程／文件／上下文版本与原文；编辑器只显示仍匹配的区域。点击同文件结果展开真实源码，跨文件定位在导航前核对对应缓冲区或磁盘源码。按 Enter／Space 也能展开。源码展开与源码模式继续使用同一 CodeMirror 语言、高亮、补全、诊断和撤销机制。

PDF.js 按 viewport 统一转换坐标，按显示密度渲染，单画布限 1600 万像素；原生图形只栅格化视口附近区域，组件销毁取消渲染并释放 PDF 资源。中性墨色沿用主题，作者彩色内容保留原色。编译／解码错误通过问题列表呈现并退回可编辑源码。

当前资源边界：快照最多 12000 文件／512 MiB，打开的文本覆盖合计 8 MiB／256 文件，PDF 最多 150 MiB；每次最多 64 个原生区域候选，单区域最多 241 行，映射阶段最多 1024 次查询并受 30 秒预算约束，原生编译超时 90 秒。超限或缺少映射提示后保留源码；不展示缺了一半的区域。大型工程首次预览仍需等待实际 TeX，不承诺每次按键都完成整篇排版。

任意 HTML 不会在 `.tex` 中被当作网页执行。通用支持来自原有 TeX 宏包与宏，而不是把作者源码传给浏览器 `innerHTML`。需要外部目录或依赖生成输出的工程可能需整理依赖；副本不包含 Git、宿主缓存、默认／配置构建目录和生成的辅助文件。

## MCP 与 SyncTeX 兼容性

插件 `apiVersion: 1`、已有贡献、命令 ID 和公开扩展接口保持不变。现有 MCP 工具名、参数与结果字段保持兼容；新增只读 `texpro_writing_context` 返回明确标记为 `source: disk` 的主文件、静态导言区、依赖、不完整标志和可识别宏，不读取编辑器内存，不保存或编译。

SyncTeX 的原有服务导出不变，底层实现从 `tex.cjs` 拆出。数值必须有效，页／行必须为正整数；锚点与可选排版盒子仍分开返回。无效值与越界路径返回失败，不再将非有限坐标传进界面。反向定位继续限制在工程真实路径之内。视口变换与实时 PDF 的版本规则不因服务拆分改变。

原生快照接口只属于桌面 preload，外部 MCP 不暴露编辑器会话或未保存内容；磁盘编译继续使用已有编译工具。此次没有已知的插件或 MCP 破坏性迁移。更严格的无效输入拒绝与以前的错误路径行为不同，但有效调用无须迁移。图片路径修正可能显露以前误按子文件目录生成的错误 TeX，需作者按工程根目录修正；不提供会与真实编译语义冲突的猜测兼容层。未来若确需破坏兼容，必须在开发文档和版本说明列出受影响版本、接口、迁移步骤及可用回退。

## 验证和接手

先运行 `npm run typecheck`、`npm run test:regression` 和 `npm run build`。原生通用回退与源码高亮流程为 `node scripts/test-flow-ui.cjs --native-writing`，原生多文件流程为 `node scripts/test-flow-ui.cjs --project-writing`，现有连续写作流程为 `npm run test:flow:ui`。涉及外部接口时补跑 `npm run test:mcp` 和实际 ASAR 外普通 Node 验证；不以开发模式成功代替发行包验证。

重点检查闭合主文件的子文件、嵌套样式、中文／空格路径、未保存样式、未知宏、图片解码、点击回源码、焦点、撤销、三主题和窄窗口。真实项目只在临时副本上编译，区分源码测试、原生界面、真实 TeX、打包与公开发布的验证状态。

`node scripts/test-flow-ui.cjs --composed-writing` 验证章节与嵌套章节原位输入、同列排版、键盘边界、中文组合输入、每文件撤销、跨文件标签改名的成组撤销、保存和自动保存；`tests/composed-editing.test.cjs` 检查命令归属、陈旧输入拒绝、外部更新与嵌套滚动归属。涉及原生回退时继续运行 `--native-writing`，不能仅靠简单章节测试证明复杂工程已通过。

常见几何宏包的适配、依赖与实际编译入口见[几何图形兼容](geometry-compatibility.md)。

AI 助手扩展单独保留在[提案](proposals/ai-writing-assistant.md)，暂不实施，也不让模型成为确定性投影的必需依赖。

## 工作室模式与无损参数

源码编辑与可视编辑共用已有工作室、草稿和预览，不把源码单独建成工具。`texVisualEdits.ts` 与 `TexVisualEditor` 只修改可识别的源范围；未知语法、作者颜色和宏保持不变。手写电路／化学／图表进入各自工作室；生成模型不再匹配时改用当前源码的参数控件，不能把旧模型覆盖回去。源码 CodeMirror 保持挂载，模式切换保留局部撤销。

在章节插入依赖时，同步登记主文件脏缓冲区后才修改章节，避免延后的状态回调被正文输入替换；保存仍走同一队列。
