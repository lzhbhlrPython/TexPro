## TeXPro 是什么

一个本地优先的 LaTeX 工作台：左边写、右边排，中间没有来回切换。源码始终是真源码，编译始终走你本机的 `latexmk`，文件始终在你自己的磁盘上。

它不是 Markdown 编辑器，也不是在线协作平台。打开它之前，你不需要注册账号、不需要把稿子传到任何服务器。

## 如何使用这些文档

[使用文档](/docs)从本篇开始，按安装、写作、编译和交付组织日常任务。开发插件、主题、MCP 接入或修改应用时，前往从开发环境开始的[开发文档](/developers)。两区共享搜索，文章侧栏与上一篇／下一篇只显示当前分区，已有文章链接保持有效。

## 准备环境

### 应用本体

| 平台 | 安装包 | 说明 |
| --- | --- | --- |
| macOS 13+ | `.dmg` | 分 Apple 芯片（arm64）与 Intel（x64）两种 |
| Windows 10+ | `.exe` | NSIS 安装包，可选安装路径 |
| Linux | `.AppImage` | 赋执行权限后直接运行；也有 deb / rpm |

安装包托管在 GitHub Releases。Nightly 每日于 Asia/Shanghai 21:23 检查相对上次成功发布的 Nightly 是否有新提交，有则测试、打包和发布；无新提交则跳过。Nightly 构建的版本号带日期，计划检查时间可能因 Actions 排队延后。

### TeX 发行版

TeXPro 不打包 TeX，需要本机已有完整发行版：

- macOS：MacTeX（或 BasicTeX + 需要的宏包）
- Windows：TeX Live
- Linux：TeX Live（发行版仓库里通常叫 `texlive-full` 或按需装）

`pdflatex`、`xelatex`、`lualatex` 任一可用即可；应用启动时探测发行版与可执行文件，探测不到会在编译前提示缺什么。中文排版建议 XeLaTeX 或 LuaLaTeX。

## 第一次打开

首次启动会给一份演示工程（`demo/`），里面有一份 `main.tex`，覆盖公式、表格、TikZ、乐谱、引用等常见元素。不用先准备自己的稿子——用它走一遍编译，能最快确认环境是否完整。

按下编译后，底部状态栏会依次出现「排版中」与「PDF 就绪 · 耗时」。如果这一步就通了，说明 TeX 环境没问题，可以打开自己的工程了。

## 打开自己的工程

用「文件 → 打开文件夹」（⌘O / Ctrl+O）选一个目录。TeXPro 会扫描其中的 `.tex`、`.bib`、图片与子目录，据此推断主文件。

主文件的判定顺序是：

| 状态 | 含义 |
| --- | --- |
| `configured` | 工程配置里写死了主文件，以它为准 |
| `detected` | 目录里只有一个合理的候选，自动选中 |
| `ambiguous` | 有多个候选，需要你指定 |
| `missing` | 目录里没有 `.tex` 文件 |
| `invalid` | 配置指向的文件不存在 |

推断不出来时，用左侧「主文件」下拉手动指定一次，选择会写进工程配置，之后打开就以配置为准。

> 工程目录下的 `.texpro/` 保存工程配置与内容快照。它是否进版本库由你决定，但对共享工程来说，通常和 `.gitignore` 一起处理更省事。

## 第一次编译

按 ⌘↩（Windows / Linux 为 Ctrl+Enter）编译。

```text
main.tex  →  latexmk（-synctex=1）  →  main.pdf
```

- 引擎默认跟随工程设置（`pdflatex` / `xelatex` / `lualatex`）
- 增量构建由 `latexmk` 负责，第二次编译通常比第一次快
- 日志同时写进 PDF 旁的构建目录，诊断面板读的是同一份
- 出错时右侧显示问题数量，点开就是诊断面板，点一条跳到出错行

编译在后台进行，不阻塞输入：你可以继续写，结果回来时只更新预览与诊断。

| 位置 | 作用 |

| 左侧栏 | 文件树、素材库、符号与全文搜索（⌘\ 收起） |

## 第一次常见问题

**编译报找不到 latexmk**：TeX 没装，或装完没重启终端 / 应用。安装器改了 PATH，旧进程拿不到。

**PDF 是空白**：多半是主文件选错了，编译的是个没有正文的 stub。检查左侧「主文件」下拉。

**中文变成方框**：引擎用了 pdfLaTeX。换成 XeLaTeX，或加载 `ctex` 宏包。

**PDF 预览不跟光标**：先编译一次让 SyncTeX 数据生成；`-synctex=1` 是默认参数，但旧工程配置里可能被覆盖了。

**打开工程很慢**：目录里 `node_modules` / `build` 之类的大目录会被跳过，但如果你的工程里有超大的图片目录，第一次扫描仍会读元信息。

## 检查和安装应用更新

准备条件：使用包含「软件更新」设置区的 TeXPro，且可以连接 GitHub。旧安装包若没有此入口，先从[GitHub Releases](https://github.com/lzhbhlrPython/TexPro/releases)手动安装新版。此操作在应用内完成，无需终端或工作目录。

- 打开「偏好设置」，找到「软件更新」，核对「当前版本」。
- 默认只检查正式版；希望接收预览构建时勾选「包含 Nightly」。此选择保存在本机，不会立即联网；Nightly 可能不够稳定。
- 点击「检查更新」。应用只在此时请求 GitHub 的公开发布信息，不发送工程路径、源码、凭据或文档内容。
- 有兼容的新版本时，核对「最新兼容版本」和「发布说明」，点击「下载更新」，通过浏览器下载当前系统与架构的安装包。
- 保存所有工作并正常退出 TeXPro，再运行安装包或替换应用；重新打开后在「当前版本」核对结果。Linux 如使用 AppImage，需要赋予新文件执行权限。

「包含 Nightly」表示同时比较正式版与 Nightly，不会强制切换或降级；基础版本先按数字比较，同基础版本的正式版优先于 Nightly，Nightly 按日期比较。不识别其他预发布格式。macOS 优先使用兼容的 DMG，Windows 使用 setup.exe，Linux 使用 AppImage；缺少兼容资产时不会推荐其他架构的包。已有同日 Nightly 被替换但版本号未改变时，检查无法识别重新构建，可从 GitHub Releases 手动获取。

「所选渠道暂无更高的兼容版本」表示所选范围内没有更高版本。没有匹配安装包会单独提示。离线、超时、限流、异常响应或发布历史超限都显示可重试错误，不会冒充已是最新；网络恢复后再次点击「检查更新」。若无法打开浏览器，使用[GitHub Releases](https://github.com/lzhbhlrPython/TexPro/releases)。应用不会自动下载、退出或替换安装，也不在启动时自动检查。
