## 第一台打字机

TeXPro 的首次正式版本使用 **v0.1.0**。**0.1.x** 系列的代号是 **Tajpilo**，世界语里的“打字机”。代号记录在根 release-series.json，发布器用于标题；标准版本、标签与安装包名保持不变，后续系列不会误继承它。

这一版的中心仍是普通 .tex：连续写作、工程主文件、保存、本地编译、诊断、PDF 与 SyncTeX 围绕同一份源码。rtex-ts 的实时预览作为 L0 融入既有 PDF 区域，不要求作者切换引擎模式；复杂绘图和模板使用按需工作空间。功能和限制见[版本列表](/releases)及仓库 docs/releases/v0.1.0.md。

## 首次发布保留基础版本

通常 major、minor、patch 会递增根版本。首次发布需要保持已存在的 0.1.0，因此在 Release patch 增加默认关闭的 initial_release。它只允许没有其他正式标签、版本与受测源码一致的首次运行，不覆盖历史。即使版本内容不需修改，仍记录运行身份，便于同一次 Actions 重试失败的上传。

完整基线、类型、构建与三平台打包全部成功后，才提交版本并建立不可覆盖的正式标签。资产先上传草稿，完整才公开；随后传准确标签刷新官网。Nightly 继续每日上海时间 21:23 检查相对上次成功 Nightly 的新提交，自动继承当前基础版本。

## 作者不必先记命令行参数

qwertysay 0.3.0 直接运行后选择简体中文或 English，再选择创建、构建、校验、打包。插件询问目录、ID、作者和语言；主题可以选择 CSS 等工具链，也可以只设置基础主题和强调色。最简主题只有清单与 LICENSE，没有 CSS、脚本、构建配置或编译依赖。

引导在执行前展示配置，回车默认取消；Ctrl+C／EOF 不开始尚未执行的操作。非交互环境不默认代答，旧完整参数留给 CI 和 npm scripts。创建不安装依赖，校验和打包不执行作者代码；明确的构建会运行可信编译器和工程配置，并可能下载依赖。

## 三篇文档各司其职

[插件 SDK](/docs/extension-development) 保留原链接，说明 API 1、清单、UTF-16、服务、修改提案、生命周期、JSON 桥接和信任边界。[qwertysay](/docs/qwertysay) 说明引导流程、语言／样式前提、输出、错误与取消。[开发 Skill](/docs/extension-skill) 说明安装、提示词、AI 工作边界、验证和交接。三篇均有英文对应篇目，SDK 仍为独立 0.2.0。

## 实际验证与边界

修改前完整基线 135 项通过；加入首次发布用例后，完整基线为 137 项、零失败、零跳过、零 TODO。qwertysay 的十一项测试覆盖引导、取消、防覆盖、无代码插件后缀和真实创建／构建／归档；另走通真实终端。九种插件语言和七种样式全部运行真实编译及归档，插件另验证宿主调用。首轮缺少工具链环境的失败没有算作通过；补齐 Java、Elm／Go 缓存和 TCSS 路径后整套重跑。

实际 npm tarball 在全新目录独立安装，验证引导模块、最简主题、TS／JS／CSS 构建与拒绝路径。注册表发布、远端 Actions、官网部署和操作系统安装验收分别核对，不以本机结果代替跨平台原生验收。安装包未签名、未公证；正式标签不会改变这一点。

Node 插件拥有用户文件、网络和进程权限，主题也可能隐藏控件或伪装提示。只启用可信来源，保留作者及依赖许可证；原生视图菜单与安全模式提供恢复。TeXPro 自有代码为 MIT，第三方归属见仓库 THIRD_PARTY_NOTICES.md。

首发三平台打包及实际包内核验通过，八个安装包已公开；qwertysay 0.3.0 已在 npm 发布，并核对 tarball 摘要及注册表独立安装。发布末段遇到草稿按标签查询返回 404，核对 Release ID 与全部资产后公开，再恢复同一次运行，未修改版本标签或重建安装包。发布器补充分页草稿查询及失败重试回归。
