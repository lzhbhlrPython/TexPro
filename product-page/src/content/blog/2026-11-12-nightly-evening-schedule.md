## 不遗漏两次构建之间的提交

Nightly 改为每日 Asia/Shanghai 21:23，对应 UTC cron `23 13 * * *`，保留手动入口。判断条件从“当天有效文件变更”改为“相对上一次成功公开且含安装包的 Nightly 是否有新提交”。空提交、合并和旧时间戳提交都计入；无新提交跳过。读取 API、缺失标签或祖先关系异常会明确失败，不能当作首次构建。失败不推进成功基线，下次继续重试。

## 正式版本在验证后递增

major、minor、patch 三个手动工作流复用相同的测试与三平台打包。全部成功后才提交根 package／lock 版本，并原子推送 main 和不可覆盖的正式标签；如果 main 已改变则要求基于最新代码重建。资产以草稿上传，完整后公开。下一次 Nightly 自动采用新的应用基础版本，独立 npm 开发工具不随之递增。

同一次 Actions 重跑识别已经提交的版本，上传或官网刷新失败无需再开一轮版本递增。正式版与 Nightly 共用排队锁，不取消进行中的发布。分支保护与 GitHub 环境审核仍由仓库配置决定。

## 验证与边界

定向回归使用临时 Git 仓库，检查版本三段重置、独立 SDK 版本保留、原子分支／标签更新、main 前进拒绝、发布失败保留草稿与同次重试。Nightly 覆盖首次构建、旧日期、空提交、合并、分页 API、缺失标签和错误处理。官网同步核对准确正式标签与资产；只在公开成功后刷新。

21:23 是计划检查时间，Actions 排队可能延后。脚本和本地构建通过不代表三个系统已完成安装运行验收；远端运行、签名和平台验收分别核对。

首次远端执行暴露了标准 Ubuntu runner 没有 pdflatex 的环境缺口，真实编译测试明确失败，未进入打包或发布。共享测试任务因此显式安装三引擎、CTeX/Fandol 与所需宏包；没有改成跳过测试。

随后实际中文 LuaLaTeX 编译定位到 `luatexja.sty` 缺失：Ubuntu 将它放在日文语言包中，只有中文语言包仍不足。共享任务显式安装该依赖，并预检 CTeX、LuaTeX-ja 和 Fandol 后继续完整基线。

三引擎与 135 项基线在 CI 全部通过后，Windows／Linux 已完成打包；macOS universal 的 ASAR 合并触发上游 glob 长度限制。当前两架构的 JavaScript 内容一致，改用不重复合并 ASAR 的路径，保留每个架构及最终包校验。本机实际 universal 目录打包和 lipo 双架构检查通过；包外 Node MCP 另作真实启动验证。此结果不替代 Intel／Windows／Linux 安装后的原生运行验收。
