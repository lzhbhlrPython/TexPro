## 写作界面不承担编译工具的复杂度

本轮任务是让插件和主题作者选择熟悉的语言，不需要为写作者再建立一种工作台。SDK 保留 API 1，宿主继续运行自包含的 JavaScript 插件，主题继续加载校验后的静态 CSS。语言编译器留在开发环境，安装仍进入既有扩展管理、停用快照和明确启用流程。

在 TypeScript、JavaScript 之外，脚手架加入 CoffeeScript、PureScript、ReScript、ClojureScript、Elm、Scala.js 和 GopherJS。大多数模板把本语言的字符串变换交给 SDK 的起始适配器；完整上下文和异步交互由 JSON bridge v1 连接。Elm 使用无 DOM 的 Platform.worker ports，处理消息和结果，而不是假装能直接调用 JavaScript 对象方法。

## 源码后缀与安装后缀分开

插件作者的 `.coffee`、`.purs`、`.res`、`.cljs`、`.elm`、`.scala`、`.go` 是开发源码。编译并打包后的入口为 `.cjs`；插件安装包统一是 `.tpp`。

主题支持 CSS、SCSS、Sass、Less、Stylus、构建时静态提取的 CSS-in-JS，以及 Thematic CSS。`.tcss` 不是新的安装后缀，也不是 Textual 的终端样式。主题最终仍分发为 `.tpt`，只含配置、静态 CSS、资源和许可证。CSS-in-JS 在开发构建阶段求值，求值脚本不会进入主题包。

新的 `qwertysay build` 先生成临时产物，通过共享校验后形成 `dist/package`。源码、构建脚本、开发依赖和缓存不混入分发目录。对源码根目录执行校验或打包会检查构建指纹；源码变更要重建，失败的重建使旧输出失效。原有自包含目录仍可直接使用。

初始化、校验、打包和 MCP 检查不会偷偷执行作者代码。开发者明确启动构建时，编译器和工程配置拥有开发者权限，也可能下载依赖。这一边界需要写在命令说明中。

## 桥接处理生命周期，宿主保留写作边界

消息协议包含调用、结果、取消、事件、配置、服务响应和销毁。调用使用独立 id，保留 UTF-16 源码范围；取消、超时和停用后忽略过期结果。桥接限制并发、消息大小和服务请求数量，清理监听与语言实例。

这些规则不代替宿主校验。修改仍是提案，需核对工程、文件、文档身份和能力，再由用户接受并通过单次编辑事务应用。磁盘读取服务仍看不到未保存的编辑器缓冲区。已经启动的服务也不能因为取消消息就宣称被操作系统撤回。

Node 插件有当前用户的文件、网络与进程权限；进程隔离不是安全沙箱。主题没有 JavaScript，也可以隐藏控件或伪装界面。原生视图菜单的重置和安全模式保留主题之外的恢复路径。

## MCP 先补可检查的接口

此前清单虽有实验性 `mcp` 动作，但并不自动成为外部 stdio 工具。本轮新增两个只读接口：`texpro_extension_capabilities` 返回格式、工具链、后缀与边界；`texpro_inspect_extension` 检查工程内已构建包的清单、摘要、大小和风险。它们不构建、不导入入口、不安装、不信任、不启用、不调用插件。

继续深化的方向是明确启用、工具白名单、稳定输入输出 schema、取消和编辑提案的过期校验；不能把“支持 MCP”简化成自动执行所有插件动作。独立 Node 服务的新依赖也同步到 ASAR 外的资源配置和检查，避免只在源码目录能运行。

## 真正编译以后才记录支持

本轮在 macOS 上逐项运行九种插件语言、七种主题样式的编译矩阵。生成插件经过归档、停用安装、明确启用、实际宿主调用与停用验证；选区包含中文和 emoji 前缀，检查 UTF-16 范围。主题检查静态产物，CSS-in-JS 的 JavaScript 没有泄漏进 `.tpt`。

真实工具链发现并修正了模板问题：Elm 编译器版本声明、Scala.js 的标准库版本约束，以及不可用的 Locale API。ClojureScript 的现代 Closure 编译器需要 Java 21+。下载故障通过官方缓存与临时验证环境处理，没有把缺少工具改成跳过。

GopherJS 要求匹配 Go 1.21 工具链；这台较新 macOS 上默认链接的开发工具无法启动，外部链接并修复本机签名后通过。这个结果不证明 Windows、Linux 或其他 macOS 版本已经完成原生验收，也不等于应用安装包已经构建。

SDK 与 qwertysay 自有代码继续以 Baolin Liu（gardenialiu）的 MIT 开源；编译后嵌入的标准库保留原协议。构建器收集可识别依赖的许可证与已知运行时通知，作者新增依赖仍需审核。不能因为工程根目录有 MIT，就把所有生成代码改称 MIT。

## 当前交付状态

SDK 与 qwertysay `0.2.0` 包含本轮编译扩展，API 版本保持 1；原有 `0.1.0` 不包含这些构建能力。开发命令、后缀、工具链、版权与边界已经同步到中英文作者说明和开发 Skill；操作见[扩展开发](/docs/extension-development)。

2026-11-12 发布核验：SDK 与 qwertysay 0.2.0 已发布到 npm，注册表 SHA-512 与验收 tarball 一致；随后从注册表重新独立安装，完成 TypeScript／JavaScript／主题构建、归档及拒绝路径验收。完整桌面基线为 135 项通过、零失败、零跳过、零 TODO。三平台应用安装包与官网部署仍以对应 Actions 的实际结果为准。

## 保留只改配色的入口

主题编译器是可选能力。最简主题仍只需 `texpro.extension.json` 和 `LICENSE`，声明需要的颜色 token 后可直接分发 `.tpt`，无需 CSS、脚本或构建配置。`examples/extensions/accent-only` 的实际打包、安装、启停回归验证了这条路径；其他颜色继承基础主题，停用后恢复。配色仍需检查来源与可读性，高自由度 CSS 主题的伪装风险说明继续保留。
