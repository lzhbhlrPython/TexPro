## 更新流程少一次跳转

前一轮更新入口会打开浏览器下载。这次继续扩展「偏好设置 → 软件更新」：安装包可以直接在应用内下载，原位查看进度、取消和重试。开启「检查后自动下载」后，主动检查发现更高兼容版本就会开始下载。此选项默认关闭，保存在本机，不会在启动时联网。

正式版与「包含 Nightly」仍使用同一套版本和平台判断。下载过程中不能切换渠道，先取消即可重新选择。没有新增更新中心或独立页面，继续采用 L2，复用纸面风格、主题 token、共享按钮、复选框和状态反馈；正文焦点与写作上下文不被下载打断。

## 完整性通过后再定位文件

主进程保存最新查询得到的候选，下载接口不接受渲染层提供的 URL 或文件路径。流式下载写入独占 .part 文件，同时计算 SHA256 和字节数，全部与 GitHub 发布数据一致后才改成安装包原名并提供「打开文件位置」。大小或校验不符不会产生可供安装的完成文件。

下载使用 HTTPS，逐跳检查 GitHub 与其资产域名，不带用户凭据；有总超时、空闲超时和磁盘空间检查。缺少摘要时明确拒绝应用内下载，保留「通过浏览器下载」供作者自行获取和核验。SHA256 代表下载完整性，不等同于操作系统开发者签名。

## 下载完成后，保存退出再安装

「打开文件位置」只在文件管理器中定位已完成的安装包，不运行程序。作者先保存所有工作并正常退出 TeXPro，再手动运行安装包或替换应用。关闭设置不会取消传输，重新打开可以继续查看；退出应用会中断，下载状态不跨应用重启恢复。目前没有断点续传，失败或取消后重新下载，完成文件保留在应用缓存中。进程崩溃或被强制结束可能遗留 .part 文件。

这个选择让日常更新流程更直接，也保持安装时机清楚可控。没有引入自动安装器、签名凭据或新的发布元数据，现有 GitHub 安装包继续适用。详细步骤见[安装与第一个工程](/docs/start)，实现边界见[版本与发布](/docs/dev-release)。

## 验证范围

完整回归 173 项通过，零失败、零跳过、零 TODO。新增下载回归使用小型受控响应，覆盖流式落盘、大小与 SHA256、缓存文件删除后的重试、取消、超时、异常重定向和符号链接路径拒绝。原生 Electron 验收覆盖检查后自动下载、完成状态、文件定位、浏览器备用入口、中英文、三主题和键盘退出；没有执行安装包。

桌面类型与构建、官网版式、类型和构建同轮核对，中文插件补齐语义键和占位符。测试没有从 GitHub 下载真实安装包，也不代表 Windows／Linux 安装验收或发布完成。
