此前的 npm 分发要求作者先生成 `.tpp` 或 `.tpt`，再把它装进 npm 包。这对已经维护源码仓库的作者增加了一步，也容易让使用者误以为 npm 只是下载器。这次补上源码路径：作者直接发布清单、LICENSE、源码与必要资源，用户仍使用 npm install 或 yarn add 管理版本。

## 两条分发路径，沿用同一个审核入口

`texpro.package` 继续指向已经打好的安装包。新的 `texpro.source` 指向包内源码目录，省略时使用包根目录。普通 npm 模块并不会因此变成扩展：包仍需满足清单、贡献、资源和大小限制。

自包含 JavaScript、静态片段、语言 JSON、主题色与静态 CSS 可以直接校验并同步。宿主保存受检副本，不原地执行 node_modules，也不会在启用时安装运行依赖。最简主题继续只需要清单和 LICENSE；选择 npm 分发时才增加 npm 的元数据。

## 编译必须是作者和用户都看得见的步骤

对于有 qwertysay.build.json 的源码包，sync 会要求先构建，而不是擅自执行 npm 的 build 脚本。用户在 qwertysay 引导中选择「构建已安装的源码扩展」，核对包名、版本与风险，确认后才复制源码、安装编译依赖并调用既有语言／样式工具链。

安装依赖默认禁用生命周期脚本；需要编译器安装器时，另有一个默认拒绝的信任选择，仅允许本次临时构建执行编译依赖安装代码。编译器或外部工具缺失时明确失败，需要用户另外审核安装或明确选择信任编译依赖安装脚本；不会为了绕过错误自动放开脚本。构建后的归档绑定源码摘要，源码改变或构建失败时，不把旧产物当成新版本。成功后还要同步到 TeXPro，选择「安装并保持停用」，最后单独决定是否启用。

## 安全提醒必须出现在命令之前

npm 上能找到一个包、完整性校验通过、有锁文件，都不能证明代码可信。编译器、工程配置和 CSS-in-JS 生成器会以用户权限运行。临时目录只是组织构建文件，不是安全沙箱；清理它也无法撤销代码对其他文件或网络的影响。

运行时同样有边界：Node 插件拥有用户的文件、网络和进程权限，主题可能隐藏按钮或伪装界面，语言包也可能用文案误导操作。安装、构建、启用需要分别判断，后一次确认不能补救前一步已经执行的恶意代码。

## 校验与交接

CLI 和宿主复用 SDK 的源码解析、路径检查和指纹。MCP 只读检查未构建 npm 源码，返回是否需要构建和风险；不会运行包管理器、编译器或插件。测试覆盖真实 TypeScript 编译、构建取消、失败与过期产物、源码快照、符号链接拒绝，以及真实 stdio 的 MCP 检查。实际安装包、完整基线与各平台验证仍分别记录，不把本地检查写成所有平台已发布。

源码路径需要 SDK 0.4.0、qwertysay 0.5.0 和对应桌面构建；历史 npm 版本与最初 v0.1.0 安装包不会自动获得新能力。完整操作、作者发布方式与限制见[用 npm／yarn 管理扩展](/docs/extension-package-management)。
