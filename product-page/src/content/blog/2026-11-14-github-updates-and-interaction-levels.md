## 从下载地址到兼容版本

TeXPro 的安装包通过 GitHub Releases 分发。新的「偏好设置 → 软件更新」让作者查看当前版本，主动检查更高的兼容版本，再通过浏览器下载安装包。默认只检查正式版；勾选「包含 Nightly」后，同时比较正式版和 Nightly。选择留在本机，不因打开设置就联网。

这次采用手动下载安装：作者查看发布说明，保存全部工作、正常退出后再安装。应用不会在启动时检查，也不会自动退出或替换自身。详细操作见[安装与第一个工程](/docs/start)。

## 比较版本，也检查安装包

检查器使用主进程提供的实际应用版本、系统与架构。数字基础版本优先，同基础版本的正式版优先于 Nightly；Nightly 按日期比较，保留旧日期格式和旧固定 nightly 标签的识别。较早版本即使发布时间更晚，也不会成为升级建议；其他预发布不会被当成 Nightly。

候选还必须有上传完成、大小非零、适配当前机器的安装包。macOS 匹配对应架构或 universal DMG，Windows 匹配 setup.exe，Linux 匹配 AppImage。实际 Linux 资产使用 x86_64 名称；查询使用迁移后的 TexPro 仓库地址。

正式版单独请求 latest，包含 Nightly 时分页读取公开发布列表。不传工程路径、源码、凭据或正文。离线、超时、限流、异常响应和超长历史明确报错，失败不能显示成“已经最新”。无兼容安装包与没有更高版本也分别说明。切换渠道或关闭设置会拒绝旧结果，避免晚到的响应改变新选择。

## L0–L3：从任务决定界面的尺度

TeXPro 以连续写作为核心。公式、表格、乐谱、电路和化学结构属于同一份文档，但专业任务也可以拥有自己的操作空间。界面复杂度应随任务复杂度生长。层级描述承载方式，不是功能价值的排名。

| 层级 | 承载方式 | 示例或判断依据 |
| --- | --- | --- |
| L0 无感增强 | 内部自动完成，复用既有流程 | realtime-tex / rtex-ts 融入现有预览与编译，不增加引擎选择页 |
| L1 原位增强 | 正文、预览、补全、诊断或上下文操作 | 在当前位置获得帮助，源码与撤销保持连续 |
| L2 按需工具 | 已有设置、弹层、侧栏或专业工具 | 更新渠道、检查结果、发布说明和下载都能在偏好设置完成 |
| L3 独立工作空间 | 独立页面或完整工作台 | 有独立流程、大画布、多区域协作或持续多阶段状态时采用 |

选择能完整承载任务的最低层级，同时保证清晰、效率和可用性。若现有空间已经拥挤，或任务需要不同的长期专注情境，可以新增职责清楚的页面。功能重要、实现复杂、需要展示成果，本身都不足以证明新页面有价值。

本次更新检查属于 L2。现有设置足够容纳完整操作，再建更新中心会重复入口。实时排版则是 L0，作者继续写即可；内部引入新引擎不意味着作者需要学习新工作空间。

## 页面有归属，退出有上下文

实施前应写清任务、层级、已有页面承载能力、新页解决的问题，以及重复入口和认知负担。复杂能力在主动进入时显现；退出后恢复写作位置、选择和滚动。简单状态、诊断和已有按钮选项应留在原有空间，必要错误也不能被藏起来。

更新区复用纸面样式、按钮与主题变量，设置使用共享焦点边界，Escape 关闭后返回此前位置。发布说明按纯文本呈现，不执行外部 HTML。还要检查 IME、撤销、异步过期与失败恢复，不能只根据截图或页面数量判断交互质量。完整开发原则见[设计语言与界面规范](/docs/dev-design)。

## 本地验证与边界

完整回归 168 项通过，零失败、零跳过、零 TODO；类型与桌面构建通过。原生 Electron 定向验收覆盖 IPC 参数拒绝、正式版／Nightly 选择、网络失败重试、下载跳转、纯文本说明、过期结果、中英文、paper／night／studio 和键盘退出。UI 验收使用受控发布响应，没有实际下载安装；真实 GitHub 查询另行验证两种渠道与资产识别。

官网同步中英文安装、发布和设计文档，并通过版式、类型与构建检查，机器可读产物由既有构建入口生成。中文插件补齐语义键、占位符与发行物构建；本地生成不代表 npm 已发布。

同日 Nightly 重建和同版本正式版替换无法通过版本号识别，可从 Releases 手动获取。此次没有自动安装、三平台安装验收、应用发布或官网部署。更新入口提供的是可核对、可选择的维护操作。
