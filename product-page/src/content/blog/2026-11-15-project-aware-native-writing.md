## 问题出在工程上下文

一个导入的多文件工程可能有自己的文档类、字体、样式文件、自定义宏和章节。只解释当前文件中熟悉的命令，单文件示例很好看，到了真实工程就会留下大量源码。继续为每个宏写专用组件，无法建立足够通用的所见即所得。

这轮先暂停 AI 功能扩展，把双通道接入与交互方案保存在提案中。当前工作集中在写作引擎：普通 TeX 仍是原件，正式排版仍由本地工具链决定，连续编辑不增加一种专用文档格式。

## 即时投影与原生排版

源扫描、工程上下文、纯投影提供器、CodeMirror 适配与 DOM 呈现分开维护。共享核心由浏览器、原生服务和 MCP 复用；主文件关闭时，子文件仍能继承静态导言区。图片路径采用工程工作目录，公式和表格使用相同的宏上下文。

普通文字、简单公式和表格保持即时编辑。快速路径不认识的宏段落、自定义环境与复杂块，使用原工程的真实 TeX 排版。后台建立临时工程副本，叠加未保存缓冲区；作者的文档类、宏包、字体与引擎继续生效。原生预览本身不会保存作者文件。

主文件引用章节时，子文件接入同一条连续文流，仍保留每个文件自己的源范围。整页 PDF 留在正式预览区，正文不变成页面截图拼贴。普通原生文字在可可靠识别时回到编辑器字体和行距；几何结构与作者颜色保留原始图形。子文件不透明区域通过 SyncTeX 盒子裁切。PDF、源码和映射属于同一个不可变副本。新输入、文件切换和旧请求的取消都需要身份校验；不能把一个旧 PDF 的位置套到新文本上。

源码高亮也继续保留。所见即所得与源码编辑有各自的价值：点击原生结果展开 TeX 后，语法高亮、补全、诊断和撤销仍来自同一个编辑器。我们分别验证排版像素和源码高亮，不用一种能力代替另一种。

## 几何宏包按语法和工具链适配

几何不仅是 TikZ 三角形。适配覆盖欧氏几何、空间坐标、二维／三维函数图、树、交换图、证明树、电路、量子线路、集合图和流程。共享描述表维护环境、命令参数、包依赖与驱动；不是在 UI 中给每个宏包堆一套组件。

真实编译检查包含 tkz-euclide、tikz-3dplot、pict2e、PGFPlots、Forest、Xy-pic、qtree、证明树、PSTricks 等代表例子。共享环境名和树语法按工程声明区分；PostScript 图稿与 Lua 布局分别核对引擎。tkz-elements 与 luadraw 仍未完成本机真实验收，外部生成程序和 shell-escape 也不会自动开放。识别一段语法，不代表已经支持该宏包的所有选项。

## 手写内容也是一等来源

手写电路与乐谱不必先经过工作室，也不需要补一份 TeXPro 元数据才可预览。无标记 MusiXTeX 环境与完整谱段参与原位呈现；图形和乐谱都能带着原始范围进入已有工作室的源码与实时预览。

源码与可视编辑属于同一工作室的两种模式，共用一份草稿和实时预览。源码使用 CodeMirror，保留高亮、输入法与局部撤销；可视参数按原始范围修改坐标、部分乐谱参数和简单函数表达式，切回源码即可看到变化。源码改动后重新识别可视参数，不用旧模型覆盖草稿。应用修改只替换原块，在正文中可一次撤销；取消不改原文。复杂源码不一定能可靠变成节点或音符表单，此时继续提供完整源码与真实排版，不用简化模型覆盖它。电路与图表工具中的源码修改同样保持权威。

图稿的主题处理区分中性墨色和作者颜色。中性线条跟随正文墨色，彩色线、标注和元件保留原色及必要的浅色承载面。透明 PDF 画布明确初始化 alpha，避免夜间出现黑底、丢失黑色文字；正文与工作室复用同一高密度图稿路径。

## L0–L3 决定能力出现的位置

L0 是无感增强，承载工程上下文、排版与缓存；L1 是原位增强，承载文字、公式、表格和原生块的显示与回源码。这两层融入现有写作流程，不增加引擎开关或新页面。

L2 适合按需打开的专业工具，L3 适合有独立完整任务流程的工作空间。复杂能力可以拥有页面，但页面需要任务边界，不能仅因为内部实现复杂就要求作者离开正文。界面复杂度应与任务复杂度匹配。

此次复用编辑器、源码模式和问题列表。支持范围扩大，也不把新的技术选择变成日常写作的配置负担。

## 验证与兼容

在 macOS 上使用真实 TeX 工具链、原生 Electron 交互和临时项目验证。一个包含中文字体、样式与多章节的实际工程副本生成了完整 PDF，主文件按连续文流展开章节，子文件保持统一纸面文字与原位图形；原生图稿按可见区域栅格化。自定义宏与环境还验证了点击回源码、焦点、未保存预览、撤销、源码高亮及三主题与窄窗口。原工程未作为验收写入目标。

纯源码回归、类型检查、构建、真实 MCP stdio 和发行包依赖另行核对；一次界面成功不代表所有平台都完成原生验收。插件 API 及原有 MCP 工具保持兼容，只增加明确标记为磁盘来源的只读工程上下文工具。桌面原生快照会话不会暴露给外部 MCP。

## 仍然存在的边界

大型工程首次预览需要等待实际 TeX。原生排版并不意味着任意宏都能像普通文字一样直接修改内部结构；可靠映射后才能投影，点击复杂内容仍展开原始 TeX。没有映射、资源超限或编译失败时保留可编辑源码并说明问题。临时副本也不是 TeX 执行沙箱。

这个方向让后续改进围绕清晰的契约推进：扩大可靠映射与编辑范围、改善复杂块的粒度和延迟，同时保持普通文件、完整源码能力和连续写作。本文记录本轮开发与本地验证，不代表已公开发布。
