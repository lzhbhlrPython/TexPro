# Website languages and release integration

Website languages are discovered from `product-page/src/i18n/languages/{code}.json`, message JSON and `src/content/docs/{locale}/{slug}.md`. Metadata declares code, autonym, HTML language, date locale and available component locale. Read `docs/website-translation.md` before adding a language. Do not scatter zh/en/eo conditionals or require contributors to edit React components and routes. Reuse discovery, fallback notices, key/placeholder validation and generators; adding a menu option alone is not complete language support. Main development maintains zh/en UI/docs; other contributors maintain their languages. Do not overwrite their translations. Blog posts remain Simplified Chinese with an explicit language notice.

The homepage's original final download area contains one shared system-package and Skill list, with inline stable/Nightly selection. Reuse row styles, focus, Reveal timing and reduced-motion behavior. Selection changes version, assets, checksums and links together. Skill uses the same row structure and reports size in KB. Use real GitHub Release data, explicit stale snapshots on API failure, and deployment-base-compatible URLs; do not add an independent channel or Skill card section.

Main stores the current stable version. Nightly targets its next patch (0.1.1 → 0.1.2-YYYYMMDD-Nightly), without committing a generated version or incrementing SDK/CLI versions. Successful stable publication triggers Nightly and the product page. Scheduled checks use the latest Asia/Shanghai 21:23 window, hourly recovery and new commits since the last successfully published installable Nightly; do not filter by commit timestamps or file diffs. Same-day manual rebuilding remains supported.

Release Skill ZIPs contain this entire self-contained directory and must match the tested source. Normal stable tags are immutable. Only an explicitly requested critical-fix replacement may use Release patch's `replacement_version`, exactly matching the current application version; it still runs the full baseline, types, build and all three platform packages before deleting that version's old Release/tag. Keep other versions intact. Retry the same Actions run after upload failure; do not silently authorize replacement from this Skill. Document the replaced build and the temporary download interruption. See `docs/release.md` for the current workflow contract.
